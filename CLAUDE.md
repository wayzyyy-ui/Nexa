# NEXA Hub: правила проекта

Дипломный проект. NEXA Hub — приложение-хаб, которое объединяет обычные устройства пользователя (телефон, ноутбук, часы, наушники, ТВ) в одну систему. Данные только настоящие: выдуманных устройств, файлов и переключателей нет (демо-режим убран). Без входа в аккаунт в NEXA не попасть: гостевого режима нет с 2026-11-06 — ветки «гость» (`uid` = null) в коде работают только в сборке без настроек Supabase (`supabase = null`).

Автор — дизайнер, а не программист. Объясняй правки простыми словами, без жаргона.

## Стиль работы

- Отвечай кратко. Во время работы почти не пиши: без пересказа шагов и объяснений очевидного.
- В конце 2–4 предложения: что сделано, какие файлы изменены, что проверить руками. Списки — только если без них никак.
- Не пересказывай код и не цитируй большие куски — только то, что просят.
- Читай только нужные для задачи файлы, проект целиком без просьбы не обходи; большие файлы — частями.
- Выводы сборки, тестов и логов не пересказывай и не вставляй целиком: только ошибки и итог.
- Задача понятна — делай сразу, без плана и вопросов; спрашивай, только если иначе можно сделать неправильно.
- Подробно объясняй, только когда просят «объясни» или «поподробнее».
- Не делай коммит и пуш без просьбы.

## Стек и запуск

- React 19 + Vite, деплой на Vercel (продакшен https://nexaru-ecosystem.vercel.app, сайт https://nexa-link.ru). Серверные функции `api/*`, регион Франкфурт (`fra1`).
- Android — Capacitor (`android/`, id `ru.nexalink.app`), ПК — Tauri 2 (`desktop/src-tauri/`). Интерфейс у всех один — `src/`, без копий; платформа — `src/lib/platform.js`, всё только для приложений — `src/native.js`.
- База и вход — Supabase. ИИ — Gemini через `api/chat.js`. Погода — Gismeteo через `api/weather.js`.
- `vercel dev` на компьютере автора не запускается; `npm run dev` поднимает только фронт без `/api`. Проверка в браузере — против имитатора Supabase (см. память «Как тестировать NEXA»).
- Тесты: `npm test` (`tests/*.test.mjs`, встроенный `node:test`), линтер `npx oxlint` (правило `no-undef` ловит забытые импорты — сборка их не ловит). Правила базы на локальном Postgres — `supabase/tests`.

## Структура кода

Зависимости сверху вниз: `src/lib` (логика без интерфейса) → `src/ui` (общие элементы) → `src/screens` (экраны) → `src/App.jsx` (`NexaApp`: состояние, навигация, связь, уведомления, окна поверх всего). Модули не импортируют друг друга по кругу и никогда не импортируют `App.jsx`. Новый код — в подходящий модуль, а не в App.jsx. Переменные модуля, которые меняет другой модуль, — только через функцию-сеттер. Подробно — `docs/code.md`.

- Не путать: `src/lib/notes.js` — уведомления (колокольчик), `src/lib/userNotes.js` — заметки; `.nx-notes` — панель уведомлений, классы заметок — `nx-notepad-*`.
- Общее состояние между вкладками — только `useSharedState` (`src/lib/shared.js`).
- Синхронизация с облаком — `useCloudList` (`src/lib/sync.js`): данные всегда живут на устройстве, облако — копия.

## Правила кода

- Комментарии в коде — на русском, коротко и понятно для новичка.
- Никаких hex-цветов в разметке: только токены `C.*`; новый цвет — новый токен в `C` и значения в обеих темах (`:root[data-theme="dark"]` / `"light"` в `src/ui/appStyles.js`).
- Не дописывай прозрачность к токенам хвостом (`${C.blue}80`) — только `color-mix(in srgb, ${C.blue} 50%, transparent)`.
- Правила для телефона — через `${PHONE_MQ}` / `${DESKTOP_MQ}` из `theme.js`, не `max-width: 768px`.
- Отступы под вырез и системную полосу — `var(--sat)` / `var(--sab)`, не `env(safe-area-inset-*)`.
- Новые окна и меню — `role="dialog"` / `role="menu"` и закрытие по Esc: тогда «Назад» браузера и Android закроет их сам.
- Свайпы: элементам, где жест мешает, — `data-no-swipe`; прокручиваемым блокам — класс `nx-scroll`.
- Скорость: при прокрутке и частых событиях не менять классы, атрибуты и CSS-переменные у `html` / `body`. Слушатели касаний — пассивные. Сначала замер, потом правка, потом замер.
- Не писать CSS-условия по содержимому атрибута `style` (Safari переписывает его по-своему).
- Потоковый ответ ассистента не писать в `setChats` на каждый кусок — только целиком в конце.
- Новых анимаций смены раздела поверх `navTransition` не добавлять.
- В русских регулярных выражениях не использовать `\b` (в JS он только для латиницы).
- Модуль плагина Capacitor не возвращать из async-функции — только в обёртке `{ api }`.
- Версии новых пакетов закреплять точно и брать выпуски старше двух недель.
- Любую правку проверять в обеих темах и на ширине 390×844. Уважать `prefers-reduced-motion`.
- Не переписывать файл целиком, если просят поправить одно место. Перед крупной переделкой предложить коммит.
- Правила проекта — в двух одинаковых файлах: `CLAUDE.md` (Claude Code) и `AGENTS.md` (Codex). Меняешь один — сделай второй точной копией. Папка `docs/` — общая для обоих.

## Визуальный язык (кратко; полностью — docs/ui.md)

- Мотив — складка: острые грани, геометрия. Шрифт — Manrope.
- Углы скруглённые: поля и мелкие плашки 10 px, средние карточки 14–16, крупные 18–20; по макету 2026-10 крупнее (таблетки 999, карточки 32–64). Прямые углы 4 px не использовать. Обводки 1 px.
- Кнопки: с текстом — «таблетки», значки — круги (классы `nx-ghost-btn`, `nx-primary`, `nx-icon-btn`, `nx-action`).
- Свечение, размытие и градиенты — только там, где их задал макет автора (список исключений — в docs/ui.md; в их числе сцена Главной — складка фоном, `FoldScene`); «стекло» — только классом `nx-glass`.
- Анимация — только когда объясняет (появление, смена состояния, переход). Бесконечных декоративных нет (кроме фона ассистента).
- Цвета бренда: синий `#4A6FFF` (устройство), мятный (связь, облако). Статусы: зелёный «в сети», красный «не в сети». Иконки — свои, геометрические.

## Контент интерфейса

- Тексты на русском, живым языком, без канцелярита.
- Никаких реальных брендов и продуктов (iPhone, Windows…): «Смартфон», «Ноутбук», «Компьютер», «Часы». Ассистент называется «AI-Ассистент».
- Исключения, где название сервиса обязательно: подпись «По данным Gismeteo» со ссылкой у любого показа погоды, Яндекс ID, Google Календарь, подпись hCaptcha на странице проверки. Логотип и копирайты Яндекс Карт не скрывать и не перекрывать.

## Безопасность (полностью — docs/security.md)

- Ключи — только в переменных окружения, не в коде, комментариях и чате. `.env*` не коммитить.
- В журналы — только коды ошибок, без текста запросов, кодов входа и токенов.
- Защита данных — RLS в базе, а не проверки в React. Новая таблица с данными пользователя — сразу RLS и правила на все 4 действия (сверка `auth.uid()`); серверная таблица без правил — дописать в `SERVER_ONLY` (`scripts/lib/sql-check.mjs`). Лимиты количества — триггером, как в `limits-fix.sql`.
- SQL-файлы `supabase/*.sql` вставляются в Supabase SQL Editor руками. Вставлено ли всё — `npm run db:check` (нужен ключ `SUPABASE_SERVICE_ROLE_KEY` в окружении; ничего не меняет, печатает, какие файлы запустить).
- Поменяли встроенный скрипт в `index.html` — пересчитать отпечаток sha256 в CSP (`vercel.json`), иначе упадёт `tests/csp.test.mjs`.

## Выпуск

- Шаги: поднять `"version"` в package.json и `VERSION` в `src/version.js` → «что нового» в `release-notes.md` (группы «Улучшилось», «Починилось», «Добавилось») и те же пункты в `ABOUT_UPDATES` (`src/screens/About.jsx`) → `npm run release:android` (APK + веб-часть) или только `npm run release:web` → проверить вывод (версия, SHA-256, ключ) → коммит «Версия X.Y.Z» (для ПК — «Версия X.Y.Z (ПК)»). Пушит автор.
- `release:web` хватает для правок интерфейса, текстов, стилей и JavaScript. Полный `release:android` нужен для разрешений, AndroidManifest, плагинов Capacitor, своих Java-модулей, виджетов, Firebase, значка и заставки, подписи, `capacitor.config.json`, `.env.android`. Сомневаешься — полный. ПК — `npm run release:desktop`; конфиг окна по воздуху не обновляется — нужен новый установщик.
- Перед выпуском сами запускаются проверки `npm run release:check` (SQL-правила, тесты, линтер, `npm audit`, тесты базы, облачная база при наличии ключа).
- Подробно (подпись, OTA, проверки APK, откат) — `docs/android.md` и `docs/desktop.md`.

## Чего не делать никогда

- `npx capacitor-assets generate` — перезапишет векторные значки Android картинками.
- Меняешь логотип — меняй одинаково `assets/logo_splash.svg`, `splash_icon.xml`, `ic_launcher_foreground_vector.xml` и `BOOT_FACETS` в `src/native.js`.
- В тестах окна ПК нельзя подменить `window.__TAURI_INTERNALS__.invoke` — команда выполнится по-настоящему. Буфер обмена ПК в тестах — общий с человеком: сохранять и возвращать в `finally`.
- Не выдумывать данные (устройства, файлы, цифры погоды, время событий): нет данных — «Нет данных».
