# NEXA Hub: правила проекта

Дипломный проект. NEXA Hub — приложение-хаб, которое объединяет обычные устройства пользователя (телефон, ноутбук, часы, наушники, ТВ) в одну систему. Это демо-интерфейс, а не настоящий продукт: данные в нём выдуманные, кроме ИИ-ассистента, который отвечает по-настоящему.

Автор — дизайнер, а не программист. Объясняй правки простыми словами, без жаргона.

## Стек и запуск

- React 19 + Vite, деплой на Vercel.
- Почти весь интерфейс лежит в одном файле `src/App.jsx`: стили inline плюс один блок `<style>` в корневом компоненте.
- `api/chat.js` — серверная функция Vercel для ИИ-ассистента (сейчас Gemini через `@google/genai`).
- Локально проект запускается командой `vercel dev` (http://localhost:3000). `npm run dev` поднимет только фронт, без `/api/chat`.
- Продакшен: https://nexaru-ecosystem.vercel.app

## Android-приложение (Capacitor)

- Папка `android/` — проект для Android Studio, `capacitor.config.json` — имя «NEXA» и id `ru.nexalink.app`.
- Сборка: `npm run build:android` (сайт с настройками из `.env.android` + копирование в `android/`), затем `npm run open:android`.
- Адрес ассистента в приложении — `VITE_API_BASE` в `.env.android` (файл в git, секретов в нём нет). На сайте адрес остаётся `/api/chat`.
- Всё, что нужно только приложению, — в `src/native.js` (на сайте ничего не делает). Кнопка «Назад» Android — в NexaApp: закрывает окно (через Esc), потом экран устройства, потом предыдущий раздел, на Главной сворачивает.
- Отступы под вырез и системную полосу: в CSS использовать `var(--sat)` и `var(--sab)`, а не `env(safe-area-inset-*)` напрямую.
- Новые окна и меню должны иметь `role="dialog"` / `role="menu"` и закрываться по Esc — тогда кнопка «Назад» закроет и их.
- Иконка приложения: исходник `assets/logo_android.svg` (из Figma). Из него рисуются `assets/icon-only.png` (целиком), `assets/icon-foreground.png` (рисунок на 74% — Android обрезает края под форму значка) и иконки сайта в `public/icons/`. Заставка — складка (`assets/splash*.png`). Пересоздать иконки Android — `npx capacitor-assets generate --android` с цветом `#01090F`, потом собрать новый APK и скопировать в `public/nexa.apk`.
- Сайт раздаёт приложение файлом `public/nexa.apk` (блок установки: карточка «Приложение NEXA» внизу мобильной Главной — `AppPromoCard`, группа «Приложение» в Настройках — `InstallSettings`; наверху Главной `InstallBanner` показывает «Вышла новая версия», если человек уже качал APK). После новой сборки APK скопировать его туда заново. Команда `build:android` сама убирает `nexa.apk` из копии сайта внутри приложения, чтобы APK не попадал сам в себя.
- Выпуск новой версии приложения: поднять "version" в package.json, затем `npm run release:android` (скрипт `scripts/release-android.mjs`): собирает APK, кладёт его в `public/nexa.apk` и пишет `public/version.json`. Версия Android (versionCode) считается из package.json: 0.5.1 → 501. Установленное приложение при запуске сравнивает свою версию с `version.json` на сайте и показывает на Главной баннер «Обновить» (`UpdateBanner`, проверка — `checkForUpdate` в `src/native.js`). Старые версии запрещены: скрипт пишет в `version.json` `minVersionCode` (по умолчанию — новая версия), и приложение старше неё показывает поверх всего экран «Эта версия устарела» (`ForceUpdateScreen`), закрыть нельзя, «Назад» сворачивает. Без интернета проверка не срабатывает. Мягкий выпуск, при котором старые версии работают и видят только баннер, — `npm run release:android -- --soft`. Собирать только на этом компьютере: обновление ставится поверх, только если APK подписан тем же ключом (`~/.android/debug.keystore`).
- Установка на экран «Домой» (iPhone): `public/manifest.webmanifest`, иконки в `public/icons/`, мета-теги в `index.html`.
- Gradle в `android/` обновлён до 9.1: Android Studio идёт с Java 25, со старым Gradle сборка падает.

## Как устроен App.jsx

1. Объект `C` с токенами цветов. Значения — CSS-переменные (`var(--bg)` и т.п.).
2. Реальные цвета обеих тем задаются в блоке `<style>`: `:root[data-theme="dark"]` и `:root[data-theme="light"]`.
3. Тема хранится в localStorage под ключом `nexa-theme`. Переключается функцией `switchTheme`, это плавный переход через View Transitions.
4. Иконки в объекте `Icon`: SVG, нарисованные кодом, параметры `c` (цвет) и `s` (размер).
5. Экраны: `ScreenHome`, `ScreenToday`, `ScreenMedia`, `ScreenFiles`, `ScreenAssistant`, `ScreenSettings`. Экран устройства `DeviceScreen` открывается поверх текущего раздела (превью интерфейса — `DevicePreview`).
6. Мобильная версия собрана правилами `@media (max-width: 768px)` в том же блоке `<style>`. Нижняя панель — `MobileTabBar`.
7. История чатов хранится в localStorage под ключом `nexa-chats`.
8. Фон экранов: `BackdropFolds` (тонкие грани складки в углах, на всех экранах) и `BackdropGrid` (сетка-чертёж, только «Настройки»). На Главной (только на компьютере) ещё `DeviceLinks` — линии от устройств к складке, точка по ним пробегает только по событию. Фон двигается только за курсором (компьютер), от наклона телефона (гироскоп; на iPhone — после разрешения в «Настройках») и при прокрутке; при `prefers-reduced-motion` неподвижен.
9. Команды ассистента: `parseCommand(text)` и список `ASSISTANT_COMMANDS` (рядом с `ScreenAssistant`), выполнение — `runCommand` внутри `ScreenAssistant`. Команды распознаются в браузере до запроса в `/api/chat`; их сообщения в истории помечены `action: true` и на сервер не отправляются. Общие данные экрана «Сегодня» — константа `TODAY`. Список команд продублирован в системной инструкции в `api/chat.js` — при добавлении новой команды обновлять оба места.
10. Синхронизация вкладок: хук `useSharedState(key, load)` — как useState, но сам сохраняет значение в localStorage и рассылает его другим вкладкам через BroadcastChannel `nexa-sync`. Так живут устройства (`nexa-devices`), файлы (`nexa-files`), расписание (`nexa-schedule`), уведомления (`nexa-notifications`) и чаты (`nexa-chats`); тема рассылается из `switchTheme`. Новое общее состояние — заводить через этот хук.
11. Центр уведомлений: колокольчик `NotificationBell` в верхней строке, последние 20 событий. Каждый `showToast` попадает туда автоматически; событие без тоста — `logEvent({ title, text, kind })`.
12. Расписание на «Сегодня» редактируемое (форма `ScheduleForm`), хранится в `nexa-schedule`; по умолчанию пустое (старый пример `SCHEDULE`, если он остался в браузере, не показывается). Курсор «сейчас» и строка «через N минут» считаются по текущему времени.
13. Плавная прокрутка колёсиком — библиотека Lenis, хук `useSmoothScroll`. Только на компьютере с мышью/тачпадом, не на экране ассистента и не при `prefers-reduced-motion`. Внутренние прокручиваемые блоки (`.nx-scroll`, окна, меню) крутятся обычно — новый такой блок должен иметь класс `nx-scroll`.

## Правила кода

- Комментарии в коде пиши на русском, коротко и понятно для новичка.
- Никаких hex-цветов прямо в разметке. Только `C.*`, а если нужен новый цвет, добавь токен в `C` и задай его в обеих темах.
- Не дописывай прозрачность к токенам хвостом вроде `${C.blue}80`: с CSS-переменными это ломается. Используй `color-mix(in srgb, ${C.blue} 50%, transparent)`.
- Любую правку проверяй в обеих темах и на мобильной ширине 390×844.
- Не переписывай файл целиком, если просят поправить одно место. Меняй точечно.
- Перед крупной переделкой предложи сначала сделать коммит.

## Визуальный язык

- Главный мотив — складка (fold): острые грани, геометрия.
- Углы: поля ввода и мелкие плашки — 4px; крупные карточки и панели (устройства, настройки, баннер установки) — 14px, значки в строках — 10px. Обводки тонкие, 1px.
- Кнопки скруглённые: кнопки с текстом — «таблетки», кнопки-значки — круги. Это задаёт общее CSS-правило для классов `nx-ghost-btn`, `nx-primary`, `nx-icon-btn`, `nx-action` — новым кнопкам достаточно дать один из них. Скошенные чипсы пути (складка) остаются как есть.
- Никакого свечения (glow), размытия и мягких пастельных карточек. Градиенты только там, где они несут смысл.
- Исключения для размытия (только они):
  - лёгкое размытие фона под окном «Добавить устройство», `backdrop-filter: blur(8px)`;
  - «вуаль» в карточке погоды: пока данные грузятся или не загрузились, значения и город размыты.
  - появление приложения при запуске: интерфейс один раз проявляется из размытия (`nx-intro` на `#root`, 0,65 с).
- «Аура» нового диалога ассистента (`AssistantAura`) — крупная складка из полупрозрачных граней. Исключение из запрета на размытие: грани размыты (`filter: blur`, 34px, на телефоне 26px) в мягкое цветное поле, края растворяются маской (`mask-image`). Так же устроена маленькая аура за ответом (`ReplyAura`): появляется, пока ассистент думает, стоит за последним ответом и через ~2 секунды после него «испаряется». Анимируется только при появлении, за курсором/наклоном и при наборе текста.
- Анимация нужна только тогда, когда она что-то объясняет: появление, смену состояния, переход. Бесконечных декоративных анимаций не делать.
- Уважать `prefers-reduced-motion`.
- Цвета бренда: синий `#4A6FFF` (устройство) и мятный (связь, облако). Статусы: зелёный «онлайн», красный «не в сети».
- Шрифты: Space Grotesk для заголовков (класс `ng-display`), цифры через `NexaNumbers`.
- Иконки свои, геометрические, а не скопированные системные.

## Контент интерфейса

- Никаких реальных брендов и названий продуктов в интерфейсе (iPhone, Windows и т.п.). Пиши «Смартфон», «Ноутбук», «Часы».
- Никаких сторонних или выдуманных брендов, кроме самой NEXA.
- Тексты интерфейса на русском, живым языком, без канцелярита.

## Безопасность

- API-ключи только в переменных окружения (`process.env`). Файлы `.env*` уже в `.gitignore`, их не коммитить и не выводить в чат.
- Не вставлять ключи в код и в комментарии.
