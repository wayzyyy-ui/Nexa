## Android-приложение (Capacitor)

- Папка `android/` — проект для Android Studio, `capacitor.config.json` — имя «NEXA» и id `ru.nexalink.app`.
- Сборка: `npm run build:android` (сайт с настройками из `.env.android` + копирование в `android/`), затем `npm run open:android`. Firebase (push) — `android/app/google-services.json`, только на этом компьютере (в .gitignore).
- Адрес ассистента в приложении — `VITE_API_BASE` в `.env.android` (файл в git, секретов в нём нет). На сайте адрес остаётся `/api/chat`.
- «Потяните, чтобы обновить» — только в приложении (`usePullToRefresh` + `PullIndicator`): страница прокручена до верха, тянем вниз больше 64 px → облако аккаунта, погода (событие `nexa-refresh`) и проверка обновления. Внутри окон, полей и `.nx-scroll` жест не срабатывает. Слушатели касаний только пассивные (без `preventDefault`: непассивный `touchmove` заставлял телефон ждать скрипт перед каждым кадром любой прокрутки), растяжку края выключает `html.nx-native { overscroll-behavior-y: none }`; насколько протянули — своё маленькое хранилище (`usePullState`), его читает только `PullIndicator`, NexaApp при натяжении не перерисовывается.
- Всё, что нужно только приложению, — в `src/native.js` (на сайте ничего не делает). Кнопка «Назад» Android — в NexaApp (`backButton` из @capacitor/app) и идёт по той же истории, что браузер (см. «Адреса и история»): экран входа / обязательное обновление / блокировка — как раньше; карточки «Продолжить здесь?» и «Устройство ищут» — Esc; иначе `history.back()`, пока есть куда (окно → экран устройства → раздел → Главная); на Главной сворачивает.
- «Назад» при открытой клавиатуре (или закрытой этим же жестом, ≤ 500 мс — `keyboardBusy` в hooks.js) только убирает её (`blur`): раньше заодно закрывалось меню ИИ в заметке.
- Отступы под вырез и системную полосу: в CSS использовать `var(--sat)` и `var(--sab)`, а не `env(safe-area-inset-*)` напрямую.
- Новые окна и меню должны иметь `role="dialog"` / `role="menu"` и закрываться по Esc — тогда кнопка «Назад» закроет и их.
- Иконка приложения: исходник `assets/logo_android.svg` (из Figma, с тенями и режимом смешивания — из него только иконки сайта `public/icons/` и `assets/icon-only.png`). Для Android — чистый логотип `assets/logo_splash.svg` (те же грани, плоские цвета с прозрачностью, без теней и размытия):
  - значок на рабочем столе — вектор `res/drawable/ic_launcher_foreground_vector.xml` (108dp, логотип в круге 66dp) на фоне `@color/nexaBg` (`mipmap-anydpi-v26/ic_launcher*.xml`);
  - заставка Android 12+ — вектор `res/drawable/splash_icon.xml` (`windowSplashScreenAnimatedIcon` в `values/styles.xml`): 288dp без подложки, логотип в видимом круге 192dp. Раньше Android растягивал в заставку PNG значка 192px — отсюда «мыло»;
  - старые заставки (Android 11 и ниже) — `res/drawable*/splash.png` и `assets/splash*.png` (2732), отрисованы из `logo_splash.svg` в точном размере, логотип — четверть короткой стороны;
  - `npx capacitor-assets generate` больше НЕ запускать: он перезапишет векторные значки картинками. Пакет `@capacitor/assets` удалён (2026-10-28, тянул уязвимые sharp и tar).
- Запуск приложения бесшовный: поверх интерфейса сразу лежит `#nx-boot` (`mountBootLogo` в `src/native.js`) — тот же логотип, того же размера (288×288, масштаб 0.1727) и в той же точке, что на заставке. `startIntro` убирает заставку (без затухания, пауза 60 мс), дальше фирменная заставка по макету автора (2026-10-23), одна шкала: грани расходятся и тают, на их месте линиями прорисовывается знак (`LOGO_MARK_D`, штрих «1 2» со сдвигом 1,002 — иначе концы линий видны точками), фон переходит в градиент Главной, знак поднимается на 22vh, под ним проявляется слово NEXA, внизу «Разработано» + mono.engineering; в `BOOT_OUT` (1150 мс; 2026-10-26 вся заставка ускорена примерно на треть по просьбе автора) — переход в Главную `bootLand`: слово NEXA уменьшается и «садится» точно на логотип шапки телефонной Главной (`.nx-home-head svg[aria-label="NEXA"]`: место и размер — по настоящему логотипу, цвет — его цвет темы) за `BOOT_LAND` (720 мс; 680 — на телефоне перелёт «рвался», 950 — казалось медленно; старт — через два кадра, слово с `will-change`), потом за `BOOT_SWAP` (180 мс) сменяется им; знак уходит вверх и тает, подпись гаснет вниз, фон растворяется, интерфейс только проявляется (`nx-intro-land` → `nx-intro-fade`, без сдвига), блоки Главной всплывают по очереди — `nx-rise` под заставкой стоит на паузе (`.nx-intro-wait #root *`). У шапки и всех её родителей всплытие выключено (inline `animation: none`): иначе логотип сдвигался на ~17 px за время перелёта и слово садилось мимо. `nx-intro-land` после перехода не снимается (иначе #root сменил бы анимацию и проявился второй раз). Нет шапки Главной или «уменьшение движения» — прежний путь: заставка тает за `BOOT_FADE` (при «уменьшении движения» — через 700 мс), интерфейс проявляется (`nx-intro`: прозрачность + 8 px). Проверено на эмуляторе: в момент смены слово и логотип шапки совпадают до десятых пикселя. Фигуры знака, слова и mono.engineering — общий `src/ui/brandArt.js` (их же берут `Logo`, `LogoMark`, `MonoLogo`). Только при запуске страницы, не при возврате из фона и не при смене разделов. С 2026-10-26 та же заставка и на сайте (`bootIntro` в native.js): один раз во вкладке (`sessionStorage nexa-boot-intro`), без системной заставки; на компьютере слово садится на NEXA вверху Главной (`.nx-home-brand-desk`), цель перелёта помечается `nx-boot-target`. В приложении для ПК (с 2026-10-28, просьба автора) заставка та же, что на сайте: один раз за запуск NEXA (`sessionStorage` окна, перезапуск из трея её не повторяет), слово садится на NEXA вверху Главной; лежит под панелью окна (`html.nx-titlebar #nx-boot { top: var(--tb-h) }`) — кнопки окна видны всё время. Нужен новый установщик. У `#root` анимация `nx-intro` — с `backwards`, не `both`: «both» оставлял transform у #root и после конца, и нижняя панель / шапка Главной (fixed, sticky) считались от страницы, а не от экрана (баг 0.15.2). Проверено на эмуляторе (кадры через отладчик WebView, анимации и таймеры замедлены в 4 раза). Меняешь логотип — меняй одинаково `logo_splash.svg`, `splash_icon.xml`, `ic_launcher_foreground_vector.xml` и `BOOT_FACETS` в `native.js`.
- Сайт раздаёт приложение файлом `public/nexa.apk` (блок установки: баннер наверху мобильной Главной — `InstallBanner`: кто не качал APK — «Приложение NEXA · Быстрее и удобнее, чем в браузере», кто качал старую версию — «Вышла NEXA … · Обновить» (`SiteUpdateBanner`); группа «Приложение» в Настройках — `InstallSettings`). После новой сборки APK скопировать его туда заново. Команда `build:android` сама убирает `nexa.apk` из копии сайта внутри приложения, чтобы APK не попадал сам в себя.
- Обновления приложения:
  - `public/version.json` (пишет `npm run copy:apk`, скрипт `scripts/copy-apk.mjs`): `version`, `versionCode`, `minVersionCode`, `apkUrl` (ссылка с номером версии `/nexa.apk?v=909` — телефон не возьмёт старый файл из кэша), `url` (`/nexa.apk`, для приложений до 0.9.9), `size`, `sha256`, `signer` (SHA-256 сертификата подписи — по `apksigner verify --print-certs`), `notes` (что нового — строки `- …` из `release-notes.md`, до 12). Версию скрипт берёт из `output-metadata.json`, который Gradle кладёт рядом с APK, — номер в version.json всегда равен номеру внутри APK. versionCode считает `android/app/build.gradle` из `"version"` в package.json (0.9.9 → 909). Повторный запуск на той же версии не поднимает minVersionCode.
  - Проверка — `checkForUpdate({ force })` в `src/native.js`: при запуске и при возврате в приложение (`resume`), сайт спрашивается не чаще раза в 6 часов, между проверками — последний ответ (`nexa-update-cache`); «потяните, чтобы обновить» и «Проверить» в Настройках — сразу. Установленная версия — `App.getInfo().build` (Capacitor App).
  - Уведомление «Вышла NEXA X», даже когда NEXA закрыта (2026-10-23, нужен новый APK): `UpdateCheckWorker.java` — WorkManager раз в ~6 часов при сети (Doze может отложить), тот же `version.json`; новое — APK (versionCode больше установленного) или веб-часть (версия новее текущей, `nativeMin` подходит). Не уведомляет: уведомления NEXA выключены, NEXA на экране (`MainActivity.inForeground`), версию NEXA уже видела сама (`known`), об этой версии уже уведомляли (`notified`). Канал `nexa-updates` (тот же, что у категории «Обновления»), до трёх пунктов «что нового», нажатие — открыть NEXA (там «Обновить»). Настройки — `SharedPreferences nexa_update_watch`, пишет `NexaUpdatePlugin.watch` ← `updateWatch(on)` в native.js после каждой проверки обновления и при смене уведомлений. Политика `UPDATE` без начальной паузы: первый запуск сразу, пока NEXA на экране, — он просто выходит. ПК: в трее уведомление Windows о новой версии было и раньше (`notify` категории updates); сайт так не умеет. Проверено на эмуляторе (NEXA свёрнута — уведомление с тремя пунктами пришло; периодическую задачу WorkManager принудительно не запустить — проверка вызывалась напрямую `UpdateCheckWorker.check`).
  - Показ: `UpdateCard` (версия, размер, «что нового», «Обновить», «Позже») — плашкой на Главной и группой «Обновление» в Настройках (там же «Установлена последняя версия · NEXA X · Проверено в …» и «Проверить»; версия — от Android). «Позже» прячет плашку на Главной для этой версии (`nexa-update-later`), в Настройках блок остаётся. Обязательное обновление (версия старше `minVersionCode`) — `ForceUpdateScreen` без «Позже», с той же установкой изнутри.
  - Установка изнутри — `NexaUpdatePlugin.java` + общий ход `updState` / `updStart` в `src/lib/updates.js` (`UpdateActions` — `src/ui/install.jsx`): сверить ключ подписи (`signer`; другой ключ — честно «поверх не встанет, удалите и поставьте заново» и «Скачать в браузере»), скачать в `cache/updates/nexa-update.apk` (только https, прогресс, «Отменить», ошибка сети — «Повторить»), сверить размер и SHA-256, проверить право «Установка неизвестных приложений» (`canRequestPackageInstalls`; нет — экран настроек, после возврата в NEXA установка продолжается сама), открыть системный установщик через FileProvider (`file_paths.xml` — `cache-path updates/`, разрешение `REQUEST_INSTALL_PACKAGES`). Тихой установки нет: Android всегда спрашивает «Установить?», так и написано; ещё может спросить Google Play Protect — подсказка «Подробнее» → «Установить без проверки». Скачанный файл удаляется при следующем запуске (`updateCleanup`). На сайте — прежняя кнопка «Скачать APK» (`ApkButton`, `SiteUpdateBanner`).

- Подпись: `android/keystore.properties` (в git не попадает, образец — `android/keystore.properties.example`; ключ `*.jks` тоже вне git). Есть файл — `npm run release:android` собирает подписанный release (`assembleRelease`), нет — debug, как раньше (`~/.android/debug.keystore`). Обновление встаёт поверх, только если APK подписан тем же ключом, что установленное приложение: при смене ключа (debug → release) все установленные приложения один раз придётся удалить и поставить заново — приложение показывает «поверх не встанет». До 0.11.6 включительно все выпуски — debug (ключ `CN=Android Debug` из `~/.android/debug.keystore`, отпечаток `f53547a3…`, APK «debuggable») — это тестовые сборки, release-ключа ещё нет.

## Работа в фоне (Android)

- Почти вся логика NEXA — JavaScript во встроенном браузере (WebView). Свернули / заблокировали экран — через несколько секунд Android «замораживает» приложение (таймеры и соединения стоят); выгрузил процесс или смахнули из «Недавних» — JS не работает вовсе. В фоне без NEXA работают только нативные части: push «Найти» (FCM, `NexaMessagingService`), напоминания о делах (`@capacitor/local-notifications`, после перезагрузки восстанавливает его `LocalNotificationRestoreReceiver`), виджеты (`WeatherWorker` — WorkManager, сам переживает перезагрузку; `ScheduleWidget` — будильник без точного времени и `APPWIDGET_UPDATE`, который система шлёт после загрузки). «Остановить» в настройках Android выключает всё это до следующего открытия — обойти нельзя и не нужно.
- Возврат в NEXA — `useReturnToApp` (`src/lib/lifecycle.js`) в NexaApp: только если NEXA была скрыта ≥ 30 с и не чаще раза в 30 с (сигналы `visibilitychange` и Capacitor `pause`/`resume` могут прийти оба — срабатывает один раз). Делает: `retry()` всех `useCloudList` (перечитать облако, заодно уходит неотправленное), `link.refresh()` (канал связи), `runUploadQueue("waiting")`. Проверка обновления, сеанса, настроек аккаунта при возврате — свои, как раньше.
- Нет и сознательно не добавляем: постоянную службу с уведомлением (foreground service), синхронизацию облака без открытой NEXA (пришлось бы копировать ключ входа в хранилище телефона), свой автозапуск после перезагрузки, WakeLock, точные будильники, новые разрешения.
