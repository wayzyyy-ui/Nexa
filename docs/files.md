# Файлы и резервная копия

> Подробности к CLAUDE.md (перенесены оттуда дословно 2026-11-11). Общие правила и оглавление — в CLAUDE.md.
> Гостевого режима нет с 2026-11-06: упоминания гостя ниже относятся только к сборке без настроек Supabase.

## Хранилище файлов

- Сведения и байты раздельно. Сведения — `fileStore.added` в NexaApp (`{ id, name, cat, folder, device, mime, size, mb, path, addedAt, updatedAt }`), у вошедшего синхронизируются с таблицей `files` (папки — `file_folders`) через `useCloudList`. Байты: вошедший — закрытая корзина Supabase Storage `nexa-files`, путь `<user_id>/<id файла>`; гость — только IndexedDB этого браузера (в облако не уходит). Демо-файлов нет.
- Модуль `src/lib/files.js`: `uploadToCloud` (XHR — настоящий процент и отмена), `fileProblem` (до 50 МБ, без html/js/exe…), `safeFileName`, `fileUrl` / `useFileUrl` (память → IndexedDB → подписанная ссылка на 1 час), `removeFromCloud` + `flushTrash` (удаление без сети — повтор позже, `nexa-files-trash@<id>`), `cacheClearScope` (при выходе), `FILE_ROWS` / `FOLDER_ROWS`.
- Полноэкранный просмотр фото — `PhotoFullscreen` (перед `FileViewer`). Второй палец пришёл позже первого (тот уже начал «смахнуть вниз / листать») — начало щипка отменяет сдвиг и полупрозрачный фон (иначе сквозь фон было видно окно файла, а фото оставалось сдвинутым): нажатие на превью загруженного фото в окне файла («На весь экран»; у демо-файлов нет — нет содержимого). Листает все загруженные фото (`photos` в `FileViewer`, новые сначала, «N из M»): стрелки и ← → на компьютере, свайп на телефоне (на сенсорном экране стрелок нет — ловили палец). Приближение: двойное нажатие (2,5×), щипок, колёсико; приближенное двигается. Закрыть: крестик, Esc / «Назад» (слушает keydown в capture — закрывается только фото, окно файла остаётся), свайп вниз. Одно нажатие прячет панели. Наверху — имя и подпись как в окне файла («Фото · Сегодня 11:56 · 519 КБ · 1 из 6»), у фото из «Файлов» (есть `onToast`) — круглые «Копировать» и «Скачать» (общий `useFileActions` с окном файла); всплывающие поверх фото (`html:has(.nx-photo-full) .nx-toast-host`). На сайте на компьютере ещё браузерный полноэкранный режим (Fullscreen API). Жесты — обычные addEventListener на сцене (не props React). Фон — токен `C.photoBg` (тёмный в обеих темах). Нет связи / не загрузилось — «Фото не загрузилось» и «Повторить».
- «Открыть» / «Скачать» — `openFileContent` (`src/ui/FileViewer.jsx`). Сайт: «Открыть» — вкладка открывается сразу по нажатию, адрес подставляется после (иначе Safari и Firefox блокируют); «Скачать» — ссылка с именем (у облака — подписанная ссылка с `download`). Приложение: встроенный браузер не скачивает и не открывает файлы — модуль `NexaFilesPlugin.java` (`nativeFile` в `src/native.js`): `save` — в «Загрузки» (Android 10+ через MediaStore, ниже — папка «Загрузки» приложения), `open` — в кэш и в другое приложение через FileProvider. Источник — подписанная ссылка облака (только https) или содержимое гостевого файла (base64); имя очищается от `/`, `..` и служебных символов.
- Окно файла без видимой полосы прокрутки (2026-10-28: `.nx-fv { scrollbar-width: none }` + `::-webkit-scrollbar`), прокрутка колесом и пальцем как раньше.
- Окно файла (макет 2026-10-26, `FileViewer`, классы `nx-fv-*`, размеры на компьютере в `--mk`): панель 734 × радиус 60 (телефон — шторка с радиусом 32 сверху), имя (карандаш — переименовать) и строка «Фото · Сегодня 11:56 · 519 КБ · 3 из 6», превью 270 px с радиусом 20 — стрелки-кружки 50 px внутри (цвет окна `C.panel`, значок `C.text`: в тёмной теме тёмные, в светлой белые) и «На весь экран» в углу; ряд `FileContentActions` (на телефоне значок над подписью, высота 58 — в строку не помещались) — «Копировать» (фото) или «Открыть» (остальное), «Скачать», «Поделиться» и красная круглая корзина (удаление с подтверждением); «Удалить файл?» — одной строкой на месте ряда кнопок, выезжает справа (`.nx-fv-confirm`, 2026-10-27); сведения строками с разделителями (последняя — «Хранится: в облаке аккаунта / в этом браузере»); градиентная «Отправить на устройство» во всю ширину, под ней «Продолжить на устройстве» (если доступно; значок `Icon.handoff` — ноутбук, телефон и дуга-стрелка, так же в меню истории ассистента и быстрых действиях) и выбор устройства.
- Плеер видео (2026-10-27, `src/ui/VideoPlayer.jsx`): в окне файла у загруженного видео — первый кадр (`VideoPoster`, `preload="metadata"`) и кнопка ▶ → `VideoPlayer` на весь экран (`.nx-video-full`, `role="dialog"`, z 800): свои кнопки (пауза, звук, полоса времени — перетаскивается, на весь экран на сайте, закрыть), панели прячутся через 2,5 с, клавиши пробел / ← → (5 с) / M / Esc (capture — закрывается только плеер). Содержимое — `fileUrl` (копия на устройстве или ссылка облака). Формат не открылся (MOV / HEVC в части браузеров) — «Видео не открылось» + «Повторить», советуем «Скачать».
- Окно файла листается: «Файлы» и «Медиа» открывают его с порядком своего списка (`setOpenFile({ id, list })` → `siblings` / `onNavigate` у `FileViewer`, `nav` — без своего появления): стрелки по бокам превью, «N из M» в подписи, ← → на клавиатуре (не в полях, не при фото на весь экран), свайп вбок по превью. У фото — «Копировать» (`clipboardWriteImage` в native.js): сайт и ПК — `navigator.clipboard.write` с PNG (`ClipboardItem` создаётся сразу по нажатию, байты — обещанием; не PNG перерисовывается), Android — `NexaFilesPlugin.copyImage` (файл в `cache/clip`, в буфер — ссылка FileProvider; нужен новый APK, старый — «обновите NEXA»).
- `FILE_SCOPE` — чьи файлы на экране (id аккаунта или "guest"); ставит NexaApp, читают `FileThumb` и `FileContentActions` («Открыть» / «Скачать» в окне файла; в приложении — всегда ссылка облака).
- Загрузка с дозагрузкой (2026-10-28): файл больше 6 МБ уходит по протоколу TUS (`src/lib/tus.js`, тесты `tests/tus.test.mjs`; в `files.js` — `resumableUpload`, `xhrRequest`, `waitOnline`): `POST /storage/v1/upload/resumable` (метаданные `bucketName`, `objectName` = `<uid>/<id>`, `contentType`, `x-upsert: false`), потом куски ровно по 6 МБ (`PATCH`, `Upload-Offset`; так требует Supabase), прогресс — по байтам. Обрыв посреди куска — пауза 1 / 3 / 8 / 15 / 30 с (без сети — ждём событие online), `HEAD` → сколько дошло, дальше с этого места; повторы кончились — обычная ошибка `network` → очередь загрузок. Адрес начатой загрузки — `nexa-tus@<uid>` (id файла → `{ url, size, at }`, не дольше 23 ч — Supabase держит сутки, только тот же сервер и размер): очередь и перезапуск NEXA продолжают ту же загрузку, а не начинают заново. Сервер её забыл (404 / 410) — новая. «Отменить» — `DELETE` загрузки на сервере. Файлы до 6 МБ — прежний один запрос. Пропуск входа берётся свежий на каждый кусок. Пока идёт долгая загрузка, копия в очереди раз в 30 с продлевает «идёт здесь» (`keepAlive` в `startUpload`) — другая вкладка не начнёт тот же файл через 2 минуты. Лимит файла — `FILE_MAX_MB` = `VITE_FILE_MAX_MB` (по умолчанию 50): 50 МБ — потолок бесплатного тарифа Supabase на файл; больше — только на платном тарифе, и тогда одинаково поднять лимит тарифа (Storage → Settings), корзины (`file_size_limit` в files-storage.sql) и `VITE_FILE_MAX_MB`. Против настоящего Supabase не проверялось — руками: большой файл, выключить и включить Wi-Fi посреди загрузки, закрыть NEXA посреди загрузки.
- Очередь загрузок без сети (только вошедший): нет сети или связь оборвалась посреди загрузки → `enqueueUpload` (содержимое — IndexedDB `<uid>:queue:<id>`, сведения — `nexa-upload-queue@<uid>`), строка «Ждёт отправки». Отправляет `runUploadQueue` в NexaApp: при входе/запуске, при возврате связи и по «Повторить»; перед каждым файлом сверяет, что сессия того же аккаунта. Повторы 5, 20, 60 с, дальше «Не загрузилось после N попыток — Повторить». id файла постоянный: ответ хранилища «уже есть» = загружено (без дублей). Выход стирает очередь вместе с остальными данными аккаунта. Отправка — только пока NEXA открыта. Страховка обычной загрузки: пока файл грузится, его копия лежит в очереди со `status: "active"`, `owner: TAB_ID`, `nextAt` = через 2 мин (`ACTIVE_STALE_MS`) — эта вкладка её не трогает и не показывает; успех / отмена / ошибка — копия убирается, обрыв сети — становится обычной строкой очереди. NEXA выгрузили посреди загрузки — при следующем открытии (через 2 мин от начала) файл догружается из очереди; тот же id — без дублей, `owner` в сведения о файле не попадает.
- Кнопки в шапке «Файлов»: «Новая папка», «Рядом» (только приложение), «Из буфера», «Добавить файл»; на телефоне сеткой по две — «Добавить файл» и «Новая папка» первым рядом (CSS `order`, классы `nx-fa-*`). «Новая папка» есть и в категории / по устройству: сбрасывает отбор и сразу открывает поле имени в корне хранилища (`folderAfterClear`).
- Выделение и меню файла (2026-10-26, `src/ui/fileSelect.jsx`): долгое нажатие на строку файла (`useLongPress`, 480 мс, сдвиг > 10 px — это прокрутка) или правая кнопка мыши — меню файла `FileMenu` (`role="menu"`, у точки нажатия, над нижней панелью): «Открыть», «Скачать» и «Копировать» (фото; оба — у загруженных, общий `useFileActions` из FileViewer.jsx, 2026-10-27), «Выделить», «Передать на устройство», «Удалить» (второй шаг — подтверждение). «Выделить» — режим выделения: у строк кружки-галочки, нажатие отмечает, внизу панель `SelectBar` (`role="dialog"` — Esc и «Назад» выходят): «Выбрано N», «Все» / «Снять», «Удалить» с подтверждением «Удалить N файлов? Вернуть нельзя». Удаление пачкой — `deleteFiles` в NexaApp (одна запись списка, одно обращение к облаку). «Скачать» в панели (круглая кнопка, 2026-10-27, `downloadSelected` в Files.jsx): по одному тем же `openFileContent` — телефон в «Загрузки», сайт — загрузки браузера (может один раз спросить про несколько файлов), ПК — «Сохранить как» на каждый (закрыли — остальные не спрашиваем); на узком телефоне «Удалить» — круглая со значком. Смена папки / поиска выходит из выделения.
- Быстрое массовое выделение (2026-10-28, просьба автора): долгое нажатие на файл (палец или левая кнопка мыши) сразу включает выделение с этим файлом — меню больше не открывается (оно осталось на правой кнопке мыши; `useLongPress` отдаёт `{ press }` / `{ context }`). Не отпуская, ведём по списку — отмечается диапазон от первой строки до той, что под пальцем (назад — снимается; уже выделенное до этого остаётся), у верхнего (130 px) и нижнего края (70 px над панелью) список сам прокручивается (`startDragSelect` в Files.jsx, строки — `data-file-idx`). Пока ведём — класс `nx-drag-select` у html, касание не прокручивает страницу: непассивный `touchmove` только у строк файлов и только во время выделения. Проверено в Chrome касаниями (390×844).
- HEIC / HEIF (фото со смартфонов): категория «Фото» и по расширению (тип часто пустой); показ — `photoUrl` в files.js: Safari рисует сам, остальным — перевод в JPEG на устройстве библиотекой `heic2any` **0.0.4** (MIT, закреплена точно, отдельный кусок ~1,35 МБ — грузится только при первом HEIC); миниатюры, окно файла и фото на весь экран. «Открыть» / «Скачать» отдают оригинал. Проверено на настоящем HEIC 3000 × 4000 — ~2,5 с.
- Новый файл без выбранной папки (корень «Хранилища», из буфера, «Поделиться», ассистент, отправка на устройство) сам попадает в папку по типу — `autoFolder` в fileStore.js (фото / видео / документы / музыка / разное; `startUpload` в NexaApp); открыта папка — в неё, как раньше.
- Файл появляется в списке только после того, как содержимое сохранено. Строки загрузки (`uploads`): процент, отмена, при ошибке — «Повторить» / «Убрать». Переименование меняет только сведения (в хранилище файл лежит по id). Удаление — сведения + объект Storage + копия IndexedDB. «Удалить мои данные» стирает и файлы.
- Объём в «Медиа и файлы» — только настоящие файлы: аккаунт — `cloudBytes()` (rpc `nexa_storage_used`, без ответа — сумма `size` загруженных) из `CLOUD_QUOTA_BYTES` (2 ГБ, как в правиле files-storage.sql) с полоской; гость — `localBytes` (что реально лежит в IndexedDB; файлы больше 25 МБ туда не попадают), лимита нет. Демо-файлы в объём не входят. Размеры — `formatBytes` (Б, КБ, МБ, ГБ; 1 КБ = 1024 Б, запятая).
- Supabase: `supabase/files-storage.sql` — таблицы `files`, `file_folders` (RLS, свои строки; `storage_path` обязан начинаться с `<user_id>/`), корзина `nexa-files` (закрытая, 50 МБ на файл), правила `storage.objects`: читать / класть / удалять только в своей папке (перезаписи и переноса нет — правила update нет). Квота 2 ГБ на аккаунт вместе с новым файлом, две проверки: правило загрузки `nexa_storage_fits(name, metadata)` — до передачи байтов (занято без объекта с тем же именем + заявленный размер `contentLength`, неизвестен — 50 МБ; чужая папка — «нет») и триггер `nexa_storage_quota` на `storage.objects` (BEFORE INSERT / UPDATE name, metadata) — в момент записи строки самим Storage: настоящий `metadata.size`, владелец — по папке пути, `pg_advisory_xact_lock` по аккаунту (одновременные загрузки по очереди), ошибка `23514 storage_quota`. Блокировку нельзя брать в правиле: Storage проверяет правило в пробной точке сохранения и откатывает её — блокировка отпускается раньше записи. Размер — только из сведений Storage, не из таблицы `files`. `nexa_storage_used()` (полоска «занято») не менялась. Уже установленная база — `supabase/storage-quota-fix.sql` (вручную в SQL Editor, повторно можно; нет права на триггер — предупреждение, остаётся проверка правилом). Приложение: отказ хранилища → само сверяет `cloudBytes()` + размер файла с 2 ГБ → «Место в облаке закончилось…» (`kind: "quota"`, без повторов). Тест — `supabase/tests/storage-quota-test.mjs` (new / migrate / old, как тест лимитов). Без этой миграции загрузка у вошедшего пишет «Облачное хранилище ещё не настроено».

## Резервная копия и восстановление

- Настройки → «Данные» (`BackupSettings`, `src/ui/backup.jsx`): «Создать резервную копию» (подпись — последняя копия на этом устройстве, `nexa-backup-last@<uid>` / без суффикса у гостя) и «Восстановить из копии». Логика без интерфейса — `src/lib/backup.js`, ZIP — `src/lib/zipStream.js` (тесты `tests/backup.test.mjs`), ход — `backupApi` в NexaApp.
- Файл `.nexa-backup` = ZIP без сжатия (фото и видео и так сжаты; архив собирается из кусков Blob, содержимое файлов не копируется в память страницы; CRC-32 — кусками по 1 МБ): `manifest.json` (format "nexa-backup", `version` — `BACKUP_VERSION` 1, app, createdAt, source { account, owner — SHA-256 от id аккаунта (сам id не пишется) или "guest", platform }, parts — сколько чего, missing — файлы без содержимого и почему, `complete`), `data/<часть>.json`, `files/<6 цифр>` (содержимое). Полной копия называется, только если всё выбранное записано.
- Входит: заметки, диалоги ассистента, расписание, память ассистента, папки и сведения о файлах (+ по желанию содержимое: копия в браузере или своя корзина облака — `fileBlob` по исходной записи с путём; путь в облаке в файл не пишется), настройки этого устройства (`SETTINGS_KEYS`: тема, Enter в ассистенте, город, уведомления, наклон, скрытие текста виджета, колонка истории). Не входит: устройства (каждое пишет себя само при входе), «Активность», журнал безопасности, уведомления, Flow и общий буфер, вход / ключи / сессии, кэши, состояние синхронизации.
- Чтение (`readBackup`): только оглавление и нужные записи (File.slice); допустимы лишь известные имена записей (иначе «посторонние записи»), без шифрования ZIP и ZIP64, «deflate» — через DecompressionStream с пределом размера; CRC каждой записи сверяется; JSON — до 64 МБ, записи проходят `CLEAN` (только известные поля и типы, лимиты длины как в базе), испорченные пропускаются с предупреждением; содержимое файла — до 50 МБ и того же размера, что в сведениях. Копия новее, чем знает NEXA (`version` > `BACKUP_VERSION`), — честный отказ «обновите NEXA»; старые форматы — шаги `MIGRATIONS` (пока пусто: версия 1 первая).
- Восстановление (`planRestore`, без записи): части по выбору; «Объединить» (по умолчанию — ничего не удаляется: того же аккаунта — по id, версия из копии только если новее; иначе — новые id, одинаковое по содержимому не дублируется, ссылки файлов на папки пересчитываются) или «Заменить» (выбранные заметки / диалоги / дела / память — ровно как в копии; отдельное подтверждение со «сейчас N → станет M» и «отменить нельзя»). Файлы никогда не удаляются — только добавляются. Ход (`backupApi.apply`): папки → файлы по одному (аккаунт — `uploadToCloud` в свою папку, без сети — обычная очередь загрузок; гость — IndexedDB, до 25 МБ на файл) с прогрессом и отменой между файлами → списки (только если не отменили; запись в localStorage сразу и с проверкой, в облако — обычной синхронизацией). Отчёт — что записано, что нет и почему.
- Сохранение файла копии: сайт — загрузка браузера; ПК — «Сохранить как» (`desktopSaveFile`); Android — `nativeSaveLarge` (native.js) → `NexaFilesPlugin.streamStart / streamWrite / streamFinish / streamCancel`: куски по 3 МБ во временный файл кэша, потом в «Загрузки» (MediaStore), тип `application/octet-stream` (с ZIP Android дописывал «.zip»). APK без этих методов (0.14.3 и раньше) — до 40 МБ по-старому, больше — «обновите NEXA». Нужен новый APK. Восстановление везде — обычный выбор файла (`<input type=file>`).
- Пароль копии (2026-10-28, `src/lib/e2e.js`): галочка «Защитить паролем» (не короче 8 знаков, дважды) — готовый ZIP шифруется целиком (`sealBlob`: PBKDF2-SHA-256 600 000 повторов → AES-GCM 256, куски по 1 МБ, у каждого свой номер и метка «последний» — подмена, перестановка и обрезка замечаются; файл начинается с `NXBKENC1`). Восстановление: зашифрованный файл → экран «Копия защищена паролем» → `openBlob` (на устройстве) → дальше как обычно; неверный пароль — «Пароль не подходит», испорченный файл — «повреждён или обрезан». Пароль не восстанавливается — так и написано. Без галочки — как раньше («копия не зашифрована»). Миграций Supabase не нужно. Проверено в Chrome: в файле нет открытого текста, неверный пароль отклонён, верный — «Что в копии».
