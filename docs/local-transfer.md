# Передача файлов в одной сети

Это реальная передача WebRTC, без загрузки содержимого в облако. Подключение устройств и запрос согласия используют существующий закрытый канал Supabase Realtime. Интернет для этого канала необходим.

## Запуск

1. Запустите проект командой `npm.cmd run dev` (PowerShell) или `npm run dev`. Для всех серверных функций используйте `vercel dev`.
2. На двух устройствах откройте актуальную NEXA, войдите в один аккаунт и подключитесь к одной локальной сети. Для сайта используйте HTTPS или localhost: HTTP по адресу локальной сети может ограничивать возможности браузера. При необходимости сначала подключите устройство существующим кодом или QR-кодом.
3. Откройте карточку другого устройства → «Отправить файлы», выберите один или несколько файлов.
4. На получателе проверьте отправителя, список и общий размер. Нажмите «Принять» либо «Отклонить». До согласия содержимое не отправляется.
5. Во время передачи доступна отмена. Счётчик отправителя основан на подтверждённых получателем байтах. Только завершающее подтверждение означает «Доставлено».
6. Полученные файлы можно сохранить по отдельности либо добавить в раздел «Файлы» (обычное хранилище аккаунта, включая его правила облачной синхронизации). Автоматического открытия нет. До сохранения файлы остаются в памяти карточки.

## Проверка между устройствами

- Передайте текстовый файл, фото и пустой файл одним запросом; сравните содержимое и размеры.
- Отклоните запрос: ни одного байта содержимого не должно быть получено.
- Передайте большой файл и отмените на каждой стороне по очереди: частичные файлы не должны становиться доступны.
- Отключите Wi-Fi во время передачи: должна появиться ошибка, без успешного раскрытия и файлов. Обнаружение остановки может занять до 20 секунд.
- Сохраните два файла с одинаковым именем: новый файл не должен заменять предыдущий без выбора пользователя. На ПК используется системное «Сохранить как», в браузере — менеджер загрузок; Android создаёт новую запись загрузки, а на Android 7–9 подбирает свободное имя.
- Проверьте обе темы, ширину 390×844, клавиатурную навигацию, Esc для отклонения запроса и системное уменьшение движения.

## Ограничения

До 50 файлов и 1 ГБ суммарно; принятые данные собираются в памяти. На слабом телефоне выбирайте меньшие файлы. Требуются WebRTC и обе открытые NEXA. Между разными сетями нет STUN/TURN и обхода маршрутизатора. Изоляция клиентов в гостевом Wi-Fi, VPN, ограничения mDNS или WebView могут мешать соединению. Автоматического перехода на облако нет. Для пакетов требуется новая версия на обоих устройствах; одиночные файлы совместимы со старым приёмником, но у него нет промежуточных подтверждений прогресса.

В этой реализации нет демонстрационного режима. Тесты `tests/direct-transport.test.mjs` запускают два экземпляра логики через подменённый канал и проверяют содержимое, согласие, отказ, отмену во время чтения и ожидания очереди, а также обрыв соединения. Они не проверяют настоящий ICE браузера, Wi-Fi и второе физическое устройство. Android-изменение защиты от совпавших имён требует новой сборки APK.
