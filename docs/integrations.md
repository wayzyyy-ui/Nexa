## Погода (Gismeteo через наш сервер)

- Сайт, приложение и виджет берут погоду **только** с `api/weather.js`: `GET /api/weather?city=kazan` (Казань по названию — когда место не определено) или `GET /api/weather?lat=…&lon=…` (`WEATHER_API` в `src/lib/weather.js` = `API_BASE + /api/weather`). Напрямую к Gismeteo и к погоде Open-Meteo клиент не ходит.
- Документация Gismeteo — https://docs.gismeteo.net/v4/weather/ (страница рисуется скриптом; спецификация — `openapi.yaml` там же). Токен — заголовок `X-Gismeteo-Token`, переменная окружения `GISMETEO_TOKEN` (Vercel и `.env.local`): только в запросе сервера к Gismeteo; клиенту не отдаётся, в журнал не пишется, в код не вписывать.
- Один запрос на город: `https://api.gismeteo.net/v4/weather/forecast/h3?coordinates=<lat>,<lon>&days=14&locale=ru-RU` — в ответе и `current` (сейчас), и прогноз с шагом 3 часа на 14 дней (из него — мин/макс по дням по местному времени, `location.time_zone_offset`). Единицы по документации: °C, м/с, мм рт. ст., %.
- Место определяет устройство (вернули по просьбе автора): `useLocation` — геолокация браузера/приложения, дальше Яндекс `ymaps3.geolocation.getPosition()` (тот же скрипт, что у карты, ключ `VITE_YANDEX_MAPS_KEY`; по описанию Яндекса — браузер и/или IP), потом по IP (ipapi.co → ipwho.is → geojs.io); название по координатам — поиск Яндекса `ymaps3.search({ text: "долгота,широта", type: ["toponyms"], limit: 1 })` с ключом `VITE_YANDEX_SEARCH_KEY` (`setApikeys({ search })`; город — первая часть `description`, если там не регион, иначе `name` — `cityFromFeature`) → BigDataCloud → Nominatim → ближайший крупный город. Каждый шаг Яндекса — не дольше 7 с (`YANDEX_LOC_MS`), нет ключей — сразу прежние сервисы; вручную — поиск `CityPicker` (геокодер Open-Meteo, это не погода) и «Определять автоматически»; ручной город — `nexa-city`. Не определилось — Казань «по умолчанию». `weatherPlace(loc)` — что спросить у сервера: по умолчанию `city=kazan`, иначе координаты, **округлённые до 0,1° (~10 км)** — соседние запросы одного города попадают в общий кеш CDN и памяти. Сервер округляет так же сам (`placeOf`), неверные координаты → 400. По названию (`CITIES`) — только kazan и moscow. Название по координатам — своё (из `useLocation`), сервер отдаёт `location.name` Gismeteo.
- Ответ сервера (свой формат): `{ source: "gismeteo" | "openmeteo", stale, city: { id, name }, time, fetchedAt, now: { temp, feels, wind, humidity, pressure, cond, text }, days: [{ date, min, max, cond, text }], attribution: { text, url } }`. `cond` — свой код для значков NEXA (`WeatherGlyph`, `condLook`, `Widgets.weatherIcon`): sun | partly | cloud | overcast | rain | snow | sleet | storm | fog — считается по описанным полям Gismeteo (гроза, тип осадков, облачность 0–25 / 26–50 / 51–75 / 76–100 %). Код `icon_weather` в документации не расшифрован — не разбираем. Текст «сейчас» — `description` Gismeteo.
- Лимит бесплатного тарифа — 1000 запросов в месяц. Защита: `Cache-Control: public, s-maxage=3600, stale-while-revalidate=1800` (CDN Vercel); свежий ответ в памяти функции (час); одновременные запросы ждут уже идущий (`inFlight`); счётчик обращений к Gismeteo `gismeteo:month` (900 за 30 дней, `allow` из `api/_lib/rate-limit.js`) — дальше сразу резерв. Расчёт: каждое новое место (0,1°) — свой запрос не чаще раза в час; один город круглосуточно — ~720 в месяц, поэтому при многих городах счётчик (900) быстро переводит всех на Open-Meteo до конца 30 дней — это честно видно по подписи источника.
- С одного адреса (sha256 IP, `clientKey`): не больше 10 новых обращений к Gismeteo в час (`IP_GISMETEO_PER_HOUR`; проверяется раньше общего счётчика — чужой перебор координат не тратит месячный лимит; сверх — резерв, не ошибка) и не больше 60 запросов к функции за 10 минут (`IP_HITS_PER_10MIN`, дальше 429 «Слишком часто…»). Обычно ответ отдаёт кеш CDN и до функции не доходит. Адреса операторов связи бывают общими — поэтому лимиты с запасом.
- Резерв: Gismeteo не ответил / 429 / нет токена / счётчик исчерпан → последний ответ из памяти функции с `stale: true` (кешируется 10 мин) → нет его — Open-Meteo (без ключа) с `source: "openmeteo"` и своей подписью → оба недоступны — 503 «Погода сейчас недоступна». Ошибки наружу без подробностей, в журнал — только код. Память функции живёт, пока экземпляр «тёплый» — после холодного старта резерв сразу Open-Meteo.
- Клиент: `useWeather(place)` — сразу последний сохранённый ответ (`nexa-weather:<место>` в localStorage, место — kazan или «55.8,49.1»), затем обновление (раз в 15 мин, «потяните», возврат сети). Строка под карточкой: «Обновлено в …», «Нет связи — данные на …» (сохранённые), «Источник недоступен — последние данные на …» (stale), ошибка с ↻. Нет данных совсем — «—» под вуалью, выдуманных цифр нет. Сводка ассистента пишет источник («По данным Gismeteo»).
- **Условие Gismeteo — брендирование**: рядом с любым показом погоды строка «По данным Gismeteo» с активной ссылкой https://www.gismeteo.ru (внешний браузер: `target="_blank" rel="noopener noreferrer"`) — `WeatherAttribution` (карточки «Погода», «Погода (завтра)», прогноз на 2 недели) и строка `weather_attr` в виджете Android. При резерве — подпись источника из ответа («Данные: Open-Meteo» → open-meteo.com), а не Gismeteo. Новый показ погоды — только с этой подписью.
- Проверка без Gismeteo: сервер с подменённым `fetch` (тест `weather_test.mjs`: запрос, заголовок, кеш, одновременные, 400, 429 → stale, 500 → Open-Meteo, 503, без токена, журнал) и сайт с настоящим `api/weather.js` (`weather_e2e.mjs`). `vercel dev` на компьютере автора не запускается.

## Google Календарь (2026-11-06)

- Только чтение основного календаря, только вошедшим. Дела из Google показываются на «Сегодня», в ближайших делах на Главной, у ассистента и в виджете (`scheduleView` в NexaApp = `mergeSchedule` из `src/lib/gcalPlan.js`), с пометкой `external`: без карандаша и корзины, подпись «Google». В `schedule`, таблицу `schedule`, резервную копию и напоминания NEXA они не попадают (напоминает сам Google). Дело на весь день — `allDay`, `time: "00:00"`, подпись «Весь день», в «ближайшее» не берётся, в виджет не идёт.
- Сервер — `api/calendar-google.js` (`start`, колбэк `GET ?code&state`, `events`, `disconnect`; тесты `tests/gcal.test.mjs`, Google и база подменены). Права — только `calendar.events.readonly`. state одноразовый, в базе хэш, 10 минут (`google_calendar_states`). Длинный ключ Google — `google_calendar.token_enc`, AES-256-GCM, ключ шифрования — `GOOGLE_TOKEN_KEY` в Vercel (сменили его — всем подключать заново). Текст дел на сервере не хранится. Google отказал (`invalid_grant`) — ключ стирается, приложение просит подключить заново.
- Клиент — `src/lib/gcal.js` (`useGcalSync` в NexaApp, `useGcal`; кеш `nexa-gcal@<uid>`, выход стирает; обновление при запуске, раз в 15 минут, при возврате не чаще раза в 2 минуты, «потяните», возврат сети). Настройки → «Приложения» → «Календарь» (`GoogleCalendarSettings`, `src/ui/gcal.jsx`). Сайт — та же вкладка, назад `/?gcal=ok|причина`; Android и ПК — внешний браузер, опрос раз в 3 с и при возврате. «Удалить мои данные» отзывает доступ.
- Название Google в интерфейсе — исключение из «без брендов», как Gismeteo и Яндекс ID.
- Ручные шаги: Google Cloud → включить Calendar API, экран согласия, OAuth-клиент «Веб», Redirect URI `https://nexa-link.ru/api/calendar-google`, `https://nexaru-ecosystem.vercel.app/api/calendar-google`, `https://nexahub.ru/api/calendar-google`; переменные Vercel `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_TOKEN_KEY` (от 24 знаков); **вставить `supabase/google-calendar.sql` в SQL Editor**. Пока настроек нет — строка «пока не настроено». В режиме «Тестирование» Google пускает только перечисленных людей, а доступ слетает через 7 дней; для всех нужна проверка приложения Google.
- Проверено (2026-11-06): тесты с подменой; WebKit, телефон обе темы и компьютер — показ, нет правки, отключение. Настоящий Google — руками, после настройки.

## Веб-уведомления сайта о новой версии (Web Push)

- Зачем: «Вышла NEXA X» системным уведомлением у сайта — браузер компьютера (вкладка может быть закрыта, браузер запущен) и телефона; на айфоне — только сайт, добавленный на экран «Домой» и открытый оттуда (iOS 16.4+; ограничение Apple). В приложениях (Android, ПК) не используется — у них свои уведомления о версии.
- Сервер — `api/webpush.js`: `GET ?action=key` (открытый ключ VAPID), `POST subscribe` (подписка браузера; с Bearer запоминает аккаунт, гостю тоже можно; адрес — только сервисы уведомлений браузеров `pushEndpointOk`: googleapis.com, mozilla.com, push.apple.com, notify.windows.com, только https), `POST unsubscribe`, `GET ?action=kick` — сервер сам берёт свой `/version.json` (самая новая из APK / web / desktop + до трёх пунктов «что нового») и, если версия новее разосланной, шлёт всем подписанным один раз: условное обновление `web_push_state` (при одновременных толчках рассылает только один); первый толчок только запоминает текущую версию. 404 / 410 от сервиса — подписка удаляется. В журнал — только числа. Лимиты: подписка 10 / 10 мин, толчок 20 / 10 мин с адреса.
- Шифрование и подпись без библиотек — `api/_lib/webpush.js` (RFC 8291 aes128gcm, RFC 8292 VAPID ES256; тесты `tests/webpush.test.mjs`: браузер расшифровывает, чужой — нет, подпись сходится, адреса).
- Кто «толкает»: сайт при открытии (не чаще раза в 6 часов, `kickWebPush` в `src/lib/webpush.js`), приложения Android и ПК — увидев новую версию (один раз на версию), плюс Vercel Cron раз в день (`vercel.json` → `crons`, на бесплатном тарифе чаще нельзя). Так рассылка уходит вскоре после деплоя.
- Нужно вручную: `supabase/web-push.sql` в SQL Editor (`web_push_subs`, `web_push_state`; RLS без правил — только сервер); ключи — `node scripts/vapid-keys.mjs` → в Vercel `WEBPUSH_PUBLIC_KEY`, `WEBPUSH_PRIVATE_KEY`, `WEBPUSH_SUBJECT` (mailto:…). Без них — «ещё не настроены на сервере». Сменили ключи — все подписки придётся включить заново.
- Интерфейс: Настройки → «Уведомления» → «Новые версии NEXA в этом браузере» (`WebPushRow`, `src/ui/webpush.jsx`; только сайт): переключатель (разрешение браузера → помощник → подписка → сервер), айфон в обычной вкладке — подсказка «Поделиться → На экран Домой», запрещено браузером — как разрешить. Нажатие на уведомление открывает NEXA (уже открытую вкладку — поверх).
- Проверено (2026-10-24): сервер с подменёнными Supabase и сервисом уведомлений — 12 из 12 (ключ, подписка, чужой адрес, первый толчок, повтор, два толчка сразу — одна рассылка, заголовки, «браузер» расшифровал «Вышла NEXA 0.15.5», 410 — удалено, отписка, без ключей); в Chrome на 390 px — строка в Настройках, помощник регистрируется. Настоящая доставка (Google / Apple) — только после ключей и деплоя, руками.
- Настройки (`ScreenSettings`, макет 2026-10-26; поиска в самих Настройках нет — значок поиска в верхней строке). Разделы — `SETTINGS_SECTIONS` в Settings.jsx (раскладку утвердил автор): Внешний вид (тема, наклон фона, облегчённый режим) · Безопасность (центр безопасности целиком — `ScreenSecurity embedded`, плюс резервная копия) · Уведомления · Память ассистента (память, Enter, улучшение ассистента) · Это устройство (сведения, Flow, общий буфер, виджет «Заметки») · Приложения (обновление, ПК, телефон); скрытый раздел «Аккаунт» (`AccountSettings`) — по карточке аккаунта. ## Отчёты о сбоях (2026-10-28)

- Свои, без сторонних сервисов и без личных данных. Ловит: необработанные ошибки и обещания (`installCrashReports` в main.jsx, `src/lib/crashes.js`) и падение интерфейса при отрисовке — `CrashBoundary` (`src/ui/crash.jsx`) вокруг `App`: вместо пустого экрана «Что-то сломалось» + «Перезагрузить» (свой маленький блок стилей обеих тем: APP_CSS живёт в упавшем приложении; убирает заставку `#nx-boot`).
- Что в отчёте (`makeReport` в `src/lib/crashReport.js`, тесты `tests/crash-report.test.mjs`): вид (error / rejection / render), имя ошибки, текст после `scrubText` (почты, ссылки — только адрес сайта, ключи и JWT, uuid, номера, числа из 5+ цифр, цитаты длиннее 30 знаков — заменяются), до 8 строк «где упало» (функция, только имя файла сборки, строка, столбец), версия, платформа, раздел (первая часть адреса: files, device…), браузер с номером («WebView 140»). Нет: аккаунта, устройства, IP, адресов страниц и файлов. Шум не шлём: «Script error.» (чужие скрипты — так же браузер прячет ошибки, брошенные не с нашего адреса), ResizeObserver, отмены запросов, сбои целиком в расширениях. Отпечаток `fp` (FNV: вид, имя, текст без чисел, первая строка) склеивает одинаковые.
- Сколько: один отпечаток — раз за запуск, не больше 10 за запуск и 30 в день с устройства (`allowSend`, `nexa-crash-day`); пачкой через 3 с, при уходе страницы — сразу; `fetch` keepalive с `text/plain` (без предварительного запроса CORS). Без сети не копим.
- Выключить на устройстве: Настройки → «Безопасность» → «Приватность» → «Отчёты о сбоях» (`CrashRow` в Security.jsx, у гостя — в его группе; `nexa-crash-reports` = "off"), по умолчанию включены — личных данных в них нет.
- Сервер — `api/errors.js`: до 10 отчётов, тело до 20 КБ, каждый заново через `cleanReport` (клиенту не верим), 10 пачек за 10 мин и 60 отчётов в час с адреса (IP — только отпечаток в счётчике), `nexa_error_hit` → таблица `error_reports` (`supabase/error-reports.sql`, **вставить вручную в SQL Editor**: ключ fp + версия, счётчик, первый / последний раз, словари платформ / браузеров / разделов — до 30 ключей, старше 90 дней и сверх 5000 строк — убираются; RLS без правил, только сервер; в `SERVER_ONLY` sql-check). Нет таблицы / ключей — короткая строка `client-error fp версия …` в журнал Vercel.
