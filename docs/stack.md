## Стек и запуск

- React 19 + Vite, деплой на Vercel.
- Код разложен по модулям (см. «Структура кода»): `src/App.jsx` — только корневой компонент `NexaApp` (состояние, навигация, связь, уведомления), экраны — `src/screens/`, общие элементы — `src/ui/`, логика без интерфейса — `src/lib/`. Стили inline плюс один общий блок `<style>` (`src/ui/appStyles.js`).
- `api/chat.js` — серверная функция Vercel для ИИ-ассистента (сейчас Gemini через `@google/genai`). Модели — список `MODELS` по очереди: основная `gemini-3.6-flash` (конкретная версия, не псевдоним: 2026-10-20 псевдоним `gemini-flash-lite-latest` указал на `gemini-3.5-flash-lite`, и ответ шёл 25 с), запасные `gemini-3.1-flash-lite` и псевдоним `gemini-flash-lite-latest`. Следующая модель — при 404 / 429 / 500 / 503 или если первые слова не пришли за 12 с от отправки (`FIRST_WORDS_MS`; у последней — без ограничения); в журнал — только номер модели и код. Стало медленно — замерить модели заново (ответ без обдумывания, время до первых слов) и поменять порядок. Обдумывание перед ответом выключаем по очереди: `thinkingLevel: "minimal"` (Gemini 3) → `thinkingBudget: 0` (старые) → без настройки (`THINKING_TRIES`): новые модели отклоняют чужую настройку ошибкой 400 «invalid argument», так ассистент однажды перестал отвечать целиком. Модель оборвалась посреди ответа — сервер дописывает `STREAM_CUT` (два невидимых U+2063 + «(ответ оборвался, нажмите "повторить")»), приложение (`STREAM_CUT_MARK` в ScreenAssistant) сохраняет ответ с `error: true`; старые версии просто покажут текст пометки. Соединение закрылось раньше конца («Остановить», ушли со страницы) — `res.on('close')` прерывает запрос к модели (`liveCtrl.abort()`), квота не тратится. Проверка — подменённый `fetch` к Google (обрыв, полный ответ, остановка).
- Ускорение ассистента (2026-10-28, `api/chat.js`, тесты `tests/chat-speed.test.mjs` с подменённым Google): тёплая функция помнит, какая настройка обдумывания подошла модели (`goodThinking`, следующий вопрос — сразу с неё, без лишнего 400), и пропускает отказавшую модель несколько минут (`restUntil`, `REST_MS`: молчала дольше 12 с — 3 мин, 429 / 503 — 2 мин, 404 — 30 мин; последнюю — никогда). `GET /api/chat?warm=1` → 204: приложение «будит» функцию при открытии ассистента (`warmChatServer` в ScreenAssistant, не чаще раза в 4 мин) — первый вопрос не ждёт холодного старта. История в запросе — последние 30 сообщений уже на устройстве (`CHAT_HISTORY_MAX`). Проверку лимитов параллельно с моделью сознательно не делали: тогда запросы сверх лимита тратили бы квоту Gemini.
- Локально проект запускается командой `vercel dev` (http://localhost:3000). `npm run dev` поднимет только фронт, без `/api/chat`.
- Продакшен: https://nexaru-ecosystem.vercel.app
- Серверные функции (`api/*`) — регион Франкфурт: `"regions": ["fra1"]` в vercel.json (по умолчанию Vercel ставит США, `iad1`: каждый вопрос ассистенту, погода и вход по QR шли через океан и обратно). Регион выбран под пользователей в России и Supabase в Европе; если проект Supabase в другом регионе — ставить ближайший к нему регион Vercel (функции ходят в базу на каждый запрос: лимиты, вход по QR, push).
