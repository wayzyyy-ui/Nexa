# Приложение для ПК (Windows, Tauri 2)

> Подробности к CLAUDE.md (перенесены оттуда дословно 2026-11-11). Общие правила и оглавление — в CLAUDE.md.
> Гостевого режима нет с 2026-11-06: упоминания гостя ниже относятся только к сборке без настроек Supabase.

## Приложение для ПК (Windows, Tauri 2) — в работе

- Папка `desktop/src-tauri/` — оболочка окна (Rust): `tauri.conf.json` (окно, CSP, установщик NSIS), `src/lib.rs`, `capabilities/default.json` (права окна), значки `icons/` (с 2026-10-26 — свой логотип ПК автора `assets/logo_pc.svg`, тёмный квадрат со складкой: SVG → PNG 1024 через Chrome → `npx tauri icon <png> -o desktop/src-tauri/icons`, папки android/ios после неё удалить; значок трея — тот же значок окна). Значок файла установщика — `assets/logo_installer.svg` (тот же + мятный кружок со стрелкой) → `icons/installer.ico` (`bundle.windows.nsis.installerIcon`). Интерфейс — тот же `src/`, без копий: `npm run build:desktop` = `vite build --mode desktop` → `dist-desktop` (без `nexa.apk`, `version.json`, `ota`, `sitemap.xml`). Сборка приложения: `npx tauri build --config desktop/src-tauri/tauri.conf.json` (сама сначала собирает `build:desktop`) → `desktop/src-tauri/target/release/bundle/nsis/NEXA_<версия>_x64-setup.exe`; версия — из package.json (`"version": "../../package.json"`). Нужны Rust (rustup) и Visual Studio Build Tools (C++); WebView2 в Windows 10/11 уже есть.
- Версии закреплены точно (выпуски старше двух недель): npm `@tauri-apps/cli` / `@tauri-apps/api` 2.12.1, crates `tauri` 2.12.1, `tauri-build` 2.7.1, `tauri-plugin-window-state` 2.5.0, связанные части выпуска 30.09.2026 — в `Cargo.lock` (свежие откатывались `cargo update -p … --precise`).
- Платформа — `src/lib/platform.js` (`detectPlatform`, `isDesktop`; тесты `tests/platform.test.mjs`): окно Tauri (`__TAURI_INTERNALS__`) или сборка `--mode desktop`. `native.js` реэкспортирует `isDesktop`. Capacitor в окне ПК отвечает «не приложение» — все Android-вызовы и так выключены, ошибок в консоли нет.
- Сервер: адрес окна — `http://tauri.localhost`, своего `/api` рядом нет → `API_BASE` из `.env.desktop` (`https://nexa-link.ru`, в git, секретов нет; запасной — тот же адрес при `isDesktop`). CORS в `api/chat.js`, `api/push.js`, `api/qr-login.js` пропускает `http://tauri.localhost`, `https://tauri.localhost`, `tauri://localhost` (погода открыта всем). На боевом сервере это заработает после пуша. QR входа и подключения (`loginUrl`, `pairUrl`, QR в «Приложение») на ПК ведут на `https://nexa-link.ru`, как в Android (адрес окна телефон не откроет). Supabase: вход по коду и по QR без перенаправлений — Redirect URLs не нужны.
- Запуск всегда с Главной (`router.js`: как Android). Яндекс Метрики нет нигде: с сайта убрана 2026-11-11 (cookie и запись экранов без согласия не нужны), из приложений — раньше (запись сессий тормозила телефон).
- Окно: 1280 × 800, минимум 1024 × 640 (раскладка компьютера, не телефона), по центру, размер и место запоминает `tauri-plugin-window-state` (`%APPDATA%\ru.nexalink.desktop\.window-state.json`). Данные (localStorage, вход) — WebView2 в `%LOCALAPPDATA%\ru.nexalink.desktop\EBWebView`. id — `ru.nexalink.desktop`.
- CSP (`tauri.conf.json` → `app.security.csp`): свой адрес, `https://nexa-link.ru`, Supabase (`https://*.supabase.co`, `wss://*.supabase.co`), Яндекс Карты (`*.yandex.ru`, `*.yandex.net`, `yastatic.net`), определение города (ipapi.co, ipwho.is, get.geojs.io, api.bigdatacloud.net, nominatim, геокодер Open-Meteo). Gismeteo напрямую не нужен. Карты из окна ПК загружаются с нынешним ключом (проверено) — менять ограничения ключа не пришлось.
- Свои команды окна — `desktop/src-tauri/src/commands.rs` (вызываются из `src/lib/desktop.js` через `invoke`; странице не даём модули Tauri с широким доступом к диску): `open_url` (только http/https → внешний браузер, crate `open`), `save_file` (байты в теле запроса, имя — заголовок `x-name` через encodeURIComponent; окно «Сохранить как» — crate `rfd`), `open_file` (во временную папку `%TEMP%\nexa-open`, чистится при запуске, → программа Windows; программы и сценарии — exe, bat, ps1, js, html, lnk… (`BLOCKED_EXT`) — не запускает, ответ `blocked`; сохранённому и открываемому файлу ставится пометка «из интернета» — `mark_from_internet`, поток `Zone.Identifier` с ZoneId=3: офисные программы открывают в защищённом просмотре), `clipboard_read` / `clipboard_write` (crate `arboard`; WebView2 на чтение буфера спрашивает «Сайт tauri.localhost хочет…»). Имя файла — `safe_name` (без папок, запрещённых знаков, CON/NUL…; тесты `cargo test --lib` в `desktop/src-tauri`). Версии закреплены: rfd 0.17.2, open 5.4.4, arboard 3.6.1 (zerocopy откачен до 0.8.59).
- Рамка окна — своя верхняя панель (2026-10-27, просьба автора; в 0.14.3–0.14.4 была своя рамка в верхней строке, потом убрана): `decorations: false`, `shadow: true` в tauri.conf.json (тень, скругление углов Windows 11, края для изменения размера, Snap и Win+стрелки остаются — у окна по-прежнему WS_THICKFRAME / WS_MAXIMIZEBOX). Панель `DesktopTitleBar` (`src/ui/titlebar.jsx`, только настоящее окно Tauri — `hasTitleBar`): 36 px, слева знак и NEXA, справа «свернуть», «развернуть / вернуть» (по `onResized` + `isMaximized`), «закрыть» (красный только при наведении; закрытие — обычный CloseRequested → трей, как раньше); перетаскивание и двойной щелчок — `data-tauri-drag-region` (двойной щелчок разворачивает сам Tauri, своего обработчика нет); окно не в фокусе — приглушено. Окна поверх экрана (`.nx-viewer`, быстрые действия, поиск) начинаются под панелью, высота окна — минус `--tb-h` (2026-10-28: верх окна файла прятался под панелью). Под панелью всё сдвигается классом `html.nx-titlebar` (`--tb-h`: body, #root, верхняя строка, меню, ассистент, Главная, заметки, всплывающие, фото / видео на весь экран). Права — capabilities: minimize, toggle-maximize, close, start-dragging, is-maximized (события — `core:default`). Нужен новый установщик (конфиг окна по воздуху не обновляется).
- Две полосы с кнопками после обновления 0.17.2 → 0.17.3: `tauri-plugin-window-state` с `StateFlags::all()` запоминал и рамку Windows (DECORATIONS) и возвращал её поверх своей панели. Теперь флаг исключён (`lib.rs`); на тестовой копии не было видно — у неё не было сохранённого состояния. Нужен новый установщик.
- Боковое меню снова sticky: в 0.17.1 у `nav` появилось inline `position: relative` (для плитки), оно перебивало sticky из appStyles — меню уезжало при прокрутке; теперь position не задаётся.
- Проверено (2026-10-27) на тестовой копии «NEXA Test» (свой identifier, настоящая NEXA не трогалась): панель 36 px, верхняя строка и меню с 36 px, без лишней прокрутки; «Развернуть» и двойной щелчок; «Закрыть» — процесс жив, окно скрыто (трей); второй запуск показывает окно; Win+↑ / Win+↓; обе темы.
- Вставка файлов: Ctrl+V с файлом или снимком вне полей ввода — в «Файлы» (обработчик `paste` в NexaApp), в поле ассистента — приложить к вопросу (`onPaste` в ScreenAssistant). Работает и на сайте.
- Внешние ссылки: окно Tauri молча не открывает `target="_blank"` и `window.open` — `installDesktopLinks` (в `main.jsx`) ловит нажатия на такие ссылки (и чужие адреса без target) и подменяет `window.open` → `open_url`. Подпись Gismeteo, «Открыть в Яндекс Картах», ссылки Flow открываются в браузере Windows.
- Файлы: «Открыть» / «Скачать» (`openFileContent`) на ПК берут байты (копия на устройстве, иначе подписанная ссылка) и отдают `open_file` / `save_file`; ответы `saved` / `cancelled` / `opened` / `blocked` («Такой файл NEXA не открывает…»). CSP `connect-src` содержит `blob:` и `data:` — иначе свой же файл не прочитать. Перетаскивание файлов в окно — `dragDropEnabled: false` (иначе Tauri забирает его себе и `drop` в «Файлах» не приходит).
- Чего нет на ПК (проверено в окне 2026-10-21): распознавание речи — WebView2 даёт `webkitSpeechRecognition`, но оно сразу падает с ошибкой `network` → `voiceKind` = null: микрофона и «Начать разговор» нет. Озвучка ответов работает (голоса Windows, в т. ч. русские). Уведомления: WebView2 молча отказывает сайту (`denied`) — поэтому свои уведомления Windows (см. ниже). Геолокация работает: WebView2 сам спрашивает разрешение своим окном. Заряд (`navigator.getBattery`) — есть.
- Правая кнопка мыши (только приложение для ПК, 2026-10-26): открывает панель быстрых действий (обработчик `contextmenu` рядом с Ctrl+K в NexaApp). Обычное меню — в полях ввода, на выделенном тексте и ссылках; у кого своё меню (файл в «Файлах») — сам отменяет событие (`preventDefault`), панель не открывается.
- Клавиатура (компьютер — сайт и ПК): Ctrl+← / Ctrl+→ — соседний раздел бокового меню (`arrowNavTarget` / `isEditable` в `src/lib/keynav.js`, тесты `tests/keynav.test.mjs`): не в полях ввода, не при открытом окне / меню / экране входа / блокировке, не на телефоне, без повтора от удержания, по кругу не ходит. Ctrl+K, Esc, «Назад» мыши — как на сайте.
- ПК как устройство (`desktop/src-tauri/src/desktop.rs`, интерфейс — `src/lib/desktop.js`):
  - `device_info`: имя компьютера (GetComputerNameExW), ноутбук или нет (GetSystemPowerStatus: нет батареи → `form: "desktop"`, «от сети»), заряд и зарядка, сеть (адаптер со шлюзом: провод важнее Wi-Fi, потом мобильная; нет — "none"), место на системном диске. `readThisDevice` на ПК берёт всё отсюда; в трее сведения обновляются (раз в 30 с), как в окне. Имя запоминается в `nexa-pc-name`.
  - Presence и запись в `devices`: `kind: "pc"` («Приложение для ПК», `peerLabel`; `isKind` в схемах его пропускает, старые версии NEXA видят его как "web"), `type` — `laptop` или новый `desktop` («Компьютер», значок монитора `Icon.desktop` / `DEVICE_ART.desktop`; превью — как у ноутбука). Название — имя компьютера; запись «Сайт на компьютере…» с того же device_id переименовывается один раз. Push «Найти» на ПК не идёт (только канал — ПК в трее и так в сети).
  - Трей: значок (нажатие — показать окно; правая кнопка — «Открыть NEXA» / «Выйти»). Крестик окна прячет NEXA в трей (`hide_to_tray`), в первый раз — уведомление «NEXA работает в трее» (отметка `tray-hint` в папке данных приложения). Выход — только из меню трея. Скрытое окно WebView2 остаётся `visibilityState: "visible"` — поэтому «не на экране» на ПК = `!document.hasFocus()` (`notify` в NexaApp). Чтобы связь и таймеры не засыпали в трее, у окна `additionalBrowserArgs`: флаги Tauri (`--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`) + `--disable-background-timer-throttling --disable-renderer-backgrounding --disable-backgrounding-occluded-windows` (свои аргументы ЗАМЕНЯЮТ аргументы Tauri — его флаги повторять).
  - Одна копия: `tauri-plugin-single-instance` 2.5.2 (с `deep-link`) — второй запуск показывает уже открытую NEXA. Автозапуск: `tauri-plugin-autostart` 2.7.0 (HKCU\…\Run, имя «NEXA», ключ `--minimized` → окно не показывается, NEXA в трее), только через свои команды `autostart_get` / `autostart_set`, по умолчанию выключен; Настройки → «Приложение для ПК» (`DesktopSettings`, `src/ui/desktop.jsx`). Окно создаётся скрытым (`visible: false`), `setup` показывает его, если это не автозапуск; window-state не запоминает видимость.
  - Ссылки `nexa://`: `tauri-plugin-deep-link` 2.6.1 (`plugins.deep-link.desktop.schemes`; схему регистрирует установщик NSIS — HKCU\Software\Classes\nexa; без установки ссылки из браузера не работают). Оболочка проверяет только «своя схема, ≤ 512 знаков, без пробелов» (`valid_link`) и копит ссылки в очереди (`take_opens`, событие `nexa-open` — так ссылка при холодном запуске не теряется); разбор — `parseNexaLink` (`src/lib/deeplink.js`, тесты `tests/deeplink.test.mjs`): `nexa://chat/<id>`, `file/<id>`, `device/<id>`, `tab/<раздел>`, `activity`, `sync`, `update`. Ссылка только открывает экран (`openTarget`: добавлены `{ chat }` и `{ file }`; нет такого — «Диалог / Файл не найден»), ничего не делает — её может подсунуть любой сайт.
  - Уведомления Windows: `systemNotifyKind` = "desktop", разрешение всегда «granted» (выключают в «Параметрах Windows»). `notify` в desktop.rs — `tauri-winrt-notification` 0.8.1; нажатие → окно поверх + ссылка `targetToLink(target)` в ту же очередь (переход — тем же `parseNexaLink`). Работает, пока NEXA запущена (в трее тоже); уведомление из Центра уведомлений после выхода из NEXA просто ничего не откроет. AUMID — identifier `ru.nexalink.desktop`: установщик ставит его ярлыку в «Пуске»; нет ярлыка (запуск собранного exe без установки) — уведомления от имени PowerShell. Напоминания о делах — как на сайте: проверка раз в 30 с, пока NEXA запущена (в трее тоже), заранее через Windows не ставятся.
- Обновления приложения для ПК (этап 4):
